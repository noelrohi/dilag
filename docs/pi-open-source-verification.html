Goal

Prove that Dilag's embedded Pi integration follows public, observable Pi usage patterns instead of relying on accidental behavior. Each checklist item should end with code links, test output, or a short note explaining why Dilag intentionally diverges.

Scope Electron main/preload bridge, renderer session flow, provider/model auth, session persistence, event streaming, abort/restart, tree navigation, skills/resources, and filesystem isolation under ~/.dilag/pi.

Comparison matrix

Dilag behavior Public proof target Acceptance criteria
Start/restart/stop runtime from Electron main Pi SDK runtime lifecycle Runtime is created once, disposed cleanly, and restart rehydrates providers/models without duplicate event listeners.
Create/get/delete sessions through bridge.agent SDK session/runtime APIs and pi-gui session driver Session IDs, directories, titles, and timestamps round-trip without renderer-only state becoming authoritative.
Prompt with text, images, selected agent, and model SDK prompt() options and event stream Renderer payload matches supported SDK inputs; unsupported fields are adapted intentionally in main process.
Stream assistant, tool, diff, question, and file-watch events SDK subscribe() event envelope Every emitted event is normalized by type guards and covered by tests.
Provider auth and model selection AuthStorage, ModelRegistry, provider docs Credentials stay under Dilag's Pi home; UI state does not leak secrets; model refresh follows provider changes.
Tree navigation/revert UI SDK navigateTree() Dilag uses Pi's tree cursor model rather than legacy revert semantics; tests cover previous/specific message navigation.
Abort current generation SDK abort() Abort is idempotent, updates UI to idle, and does not orphan session state.
Skills/resources installation Pi resource loader and skills docs Installed skills are discoverable by Pi while session-local skills remain isolated from app assets.
Filesystem isolation Public SDK storage conventions plus Dilag requirement Pi data lives under ~/.dilag/pi; workspace files are only touched through explicit session directories/tools.

Intentional divergences

Divergence Reason Risk/Future work
Dilag uses ~/.dilag/pi instead of default ~/.pi/agent. App data isolation. SDK explicitly supports custom agentDir, custom AuthStorage, and custom ModelRegistry. Low risk; apps/desktop/electron/ipc/paths.ts:27-29 centralizes the path.
Dilag writes design skills into the current workspace's .agents/skills. Dilag needs session-local mobile/web design skills discoverable by Pi resource loading without mutating global Pi assets. Intentional. Public SDK docs list .agents/skills project discovery.
Dilag does not expose raw Pi events to React. Renderer consumes a stable Dilag contract while Electron main adapts Pi event names, tool states, questions, and idle status. Covered by session-store/chat tests; keep adding tests when new Pi event types are surfaced.
Dilag uses a lightweight session map, not pi-gui's full SessionSupervisor. Dilag currently needs direct session CRUD and renderer bridge events, not pi-gui's workspace catalog layer. Revisit if Dilag adds cross-workspace Pi catalogs, session import, or richer runtime replacement flows.
OpenAI subscription auth is displayed as OpenAI while backend may use openai-codex. Provider choice is a UX alias; backend provider ID remains explicit for Pi auth. Regression covered by model selector logo tests.
